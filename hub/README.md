# 株主優待ハブ(スプレッドシートとの同期)

株主優待メモアプリの優待・受取・特典を、自分のGoogleスプレッドシート「株主優待ハブ」に置いて、iPadなど他の端末や、ほかのAI(さくらなど)と共有するための受け口です。読書メモの「読書ハブ」と同じ仕組みで、費用はかかりません。

- アプリのデータは各端末の中(IndexedDB)にもあり、開いたとき・アプリに戻ったとき・書いてから数秒後に、変わった分だけをやり取りします。
- 同じ行を二つの端末で直したときは、後から直したほうが残ります。削除も伝わります(表の `deleted` が `1` になります)。
- **表を直接書き換えてもアプリに届きます**(読書ハブとの違い)。人やほかのAIがシートを直すと、次の同期のときにハブが行の指紋(`_sync` シート)と比べて見つけ、新しい番号(rev)を振ってアプリへ流します。行を消せば削除として、id のない行を足せば id を振って新しい行として流れます。
- 保有株数は別のスプレッドシート「ポートフォリオ」のタブ「保有株式」から**読むだけ**です。ハブには複製せず、アプリが証券コードで結合して表示します。

## 準備(最初の1回、パソコンで行うのが楽です)

1. スプレッドシート「株主優待ハブ」を開きます(`benefits`・`receipts`・`campaigns` のタブがあるもの)。
2. メニューの「拡張機能」→「Apps Script」を開きます。
3. 最初からある `コード.gs` の中身を全部消して、[Code.gs](https://raw.githubusercontent.com/tadamasa/yutai-memo/main/hub/Code.gs) の中身を貼り、保存します。
4. 上の関数の選択欄で `setup` を選び、「実行」を押します。
   - 権限の確認が出たら、自分のアカウントを選び、「詳細」→「(安全ではないページ)に移動」→「許可」と進みます。自分で作ったスクリプトなので問題ありません。ポートフォリオを読むため、「スプレッドシートの表示・編集」の許可を求められます(ポートフォリオには書き込みません)。
   - 下の実行ログに「合言葉: …」が出ます。これを控えます。
   - このとき、表の今の内容が台帳(`_sync` シート)に記録されます。`_sync` は消したり編集したりしないでください。
5. 右上の「デプロイ」→「新しいデプロイ」を開き、種類の歯車から「ウェブアプリ」を選びます。
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **全員**
   - 「デプロイ」を押し、出てきた「ウェブアプリのURL」(`…/exec` で終わるもの)をコピーします。
6. 株主優待メモアプリの「設定」→「株主優待ハブ(同期)」に、URLと合言葉を入れて「接続して同期する」を押します。
7. iPadでは、同じアプリ(https://tadamasa.github.io/yutai-memo/)をホーム画面に追加し、同じURLと合言葉で接続します。

URLと合言葉を知っている人は読み書きできるので、他の人には教えないでください。

## さくら(Muse)用の合言葉

1. Apps Script の関数の選択欄で `setupSakura` を選び、「実行」を押します。実行ログに「さくら用合言葉: …」が出ます。
2. その合言葉を、さくらの保管庫に登録します(チャットなどには貼らないでください)。URLは今のものをそのまま使います。
3. さくら用の合言葉では、追加・更新と読み取り(pull・holdings)はできますが、**削除はできません**(送っても `skipped` に入って無視されます)。
4. 止めたいときは、「プロジェクトの設定」→「スクリプト プロパティ」から `SAKURA_TOKEN` を削除します。端末の同期には影響しません。

## 口(API)

すべて JSON を返します。合言葉は GET では `?token=`、POST では本文の `token`(または `?token=`)で渡します。POST は `Content-Type: text/plain;charset=utf-8` で送ります(`application/json` だと事前確認で失敗します)。

| 口 | 返すもの |
|---|---|
| `GET ?action=ping` | `{ "ok": true, "app": "yutai-hub" }`(合言葉なし。URLの確かめ用) |
| `GET ?action=pull&since=<rev>&token=…` | `{ ok, rev, more, benefits:[…], receipts:[…], campaigns:[…] }`。`since` より新しい行だけを rev の古い順に最大400件。`more` が `true` なら、返ってきた `rev` を次の `since` にしてもう一度呼ぶ |
| `GET ?action=holdings&token=…` | `{ ok, at, holdings:[{ code, name, shares, price }] }`。ポートフォリオ「保有株式」の4行目から、A=証券コード、B=銘柄名、D=株数、F=現在株価。証券コードでない行(空行・リンクの行)は飛ばす |
| `POST { token, benefits:[…], receipts:[…], campaigns:[…] }` | `{ ok, rev, saved, skipped:[id…], current:{ benefits, receipts, campaigns } }`。各要素は表の列名をキーにした1行で、`id` で upsert。`mtime` が表と同じか古いものは捨てて `skipped` に入れ、その行の表の今の中身を `current` に返す(端末はそれで手元を表に合わせる)。`deleted: true` は墓標(行は残して `deleted` を `1` に) |

- 行の `rev` はハブが振る通し番号で、端末からは送りません。`mtime` は ISO 8601 の文字(例 `2026-11-13T09:30:00.000Z`)。最初に入っていた行の `2026-11-13` のような日付だけの値は、その日の0時(UTC)とみなします。
- pull で返る行の `deleted` は `true` / `false`、`rev` は数です。表の中では `deleted` は `1` / `0` の文字です。

例: さくらが受取を1件足す

```
POST {ハブのURL}
Content-Type: text/plain;charset=utf-8

{"token": "<さくら用合言葉>", "receipts": [{"id": "rcp-2702-xxxx", "code": "2702", "company_name": "日本マクドナルドホールディングス(株)", "benefit_name": "食事優待券", "fiscal_year": "2026年6月", "received_at": "2026-09-20", "expires_at": "2027-03-31", "status": "未使用", "mtime": "2026-11-13T10:00:00.000Z"}]}
```

## 表(シート)の約束

| シート | 列 |
|---|---|
| `benefits`(優待マスタ。1銘柄1行、id は `ben-<証券コード>`) | id, code, company_name, has_benefit(あり/なし/要確認), benefit_category, benefit_detail, tiers, record_dates, arrival_timing, validity_note, official_url, checked_at, benefit_status, memo, rev, mtime, deleted |
| `receipts`(受取・使用記録) | id, code, company_name, benefit_name, fiscal_year, received_at, expires_at, status(未使用/一部使用/使用済/失効), used_at, memo, rev, mtime, deleted |
| `campaigns`(特典・キャンペーン) | id, code, company_name, title, deadline, conditions, apply_route, apply_url, status(未確認/応募予定/応募済/当選/落選/見送り/対象外), memo, rev, mtime, deleted |
| `_sync`(台帳。触らない) | kind, id, rev, hash, gone |

- 列は**見出しの名前で**読み書きします。列の順番を並べ替えたり、右に自分用の列を足したりしても壊れません(ハブは自分の列にしか書きません)。足りない列があれば、ハブが右端に見出しを足します。
- ハブが書く列は書式なしテキストにします(日付や証券コードが勝手に変換されないように)。日付は `YYYY-MM-DD` で書いてください。
- 表を直接直したときの `mtime` は、ハブが気づいた時刻になります。その時刻より前に端末で書いて、まだ送っていなかった変更は、表の内容に負けます。

## スクリプトを新しくするとき

Code.gs を貼り替えて保存したら、「デプロイ」→「デプロイを管理」→ 鉛筆の印 → バージョン「新バージョン」→「デプロイ」。URLは変わりません(「新しいデプロイ」を作るとURLが変わるので注意)。

## うまくいかないとき

- 「応答を読めませんでした」: URLが `/exec` で終わっているか、デプロイのアクセスが「全員」かを確かめます。
- 「合言葉が違います」: `setup` の実行ログの合言葉を、前後の空白なしで入れます。
- 保有株数が更新されない: ポートフォリオのシート名が「保有株式」か、見出しが3行目・データが4行目からかを確かめます。別のシートを使うときは、スクリプト プロパティに `PORTFOLIO_ID` を足します。
